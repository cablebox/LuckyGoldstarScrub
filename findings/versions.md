## CA bundle details

- Bundle: Debian-style `ca-certificates 20180409` => Mozilla NSS ~2.20/2.22 (spring 2018); `R/usr/share/ca-certificates/mozilla/*.crt` = 133 PEMs, mtime 2026-04-15 (rebuilt but contents old). LG also adds `usr/share/ca-certificates/sdp/sdp-ca.pem`. (The "certificate-update-manager" service in the opkg dependency list may update the store at runtime; **not analyzed**.)
- Parsed with host `openssl x509 -enddate` (data-only): **19 of 134 cert files expired as of 2026-10-18**: AddTrust External CA Root (2020-05-30), Baltimore CyberTrust Root (2025-05-12), Certplus Class 2 Primary CA (2019), Cybertrust Global Root (2021), **DST Root CA X3** (2021-09-30, the Let's Encrypt cross-sign root that caused the 2021 outage), Deutsche Telekom Root CA 2 (2019), E-Tugra (2023), GeoTrust Global CA (2022), GlobalSign Root R2 (2021), Hongkong Post Root CA 1 (2023), QuoVadis Root CA (2021), SECOM Trust.net (2023), Sonera Class2 (2021), Staat der Nederlanden EV Root (2022) and Root G2 (2020), Trustis FPS (2024), TURKTRUST (2023), Visa eCommerce Root (2022). Expired roots are mostly harmless by themselves, but old cross-sign chains (AddTrust) cause validation failures, and keeping DST X3 can cause trust confusion on OpenSSL 1.0.2.
- **Distrusted/removed-by-Mozilla roots still present** (by name; Mozilla distrust dates from memory): Symantec family (VeriSign Class 3 G3/G4/G5, Universal Root, GeoTrust x6, thawte x3) - distrusted by Mozilla/Chrome 2018-2019 after the Symantec PKI issue; **Certinomis Root CA** (distrusted 2019); **TrustCor ECA-1/RootCert CA-1/CA-2** (distrusted 2022-23); **E-Tugra** (distrusted 2023); TUBITAK Kamu SM (removed ~2020-21?) (?); Entrust roots (Entrust distrust by Chrome/Mozilla late 2024: Entrust Root CA, EC1, G2) (?); OpenTrust Root CA G1-G3. Impact: a still-accepted CA that browsers no longer trust widens the MITM surface.
- **Missing newer roots**: no ISRG Root X2, no Google Trust Services (GTS Root R1-R4), no Microsoft/Amazon newer ECC chains, no newer DigiCert/Sectigo roots (ISRG X1 + Amazon Root 1-4 + DigiCert Global G2 **are** present). Sites using GTS-only chains (Google services) and other modern roots rely on cross-sign or the runtime updater. Chromium's own (68-era) built-in store behaves similarly unless the system store is used.

## Implications

**Security exposure.** The firmware was compiled in April 2026 but ships a 2017-2018 userland: Linux 4.4.84, glibc 2.28, OpenSSL 1.0.2p (public EOL Dec 2019), curl 7.61, expat 2.2.6, zlib 1.2.11, sqlite 3.23, freetype 2.9.1, libwebp 1.0.0, Node 8.12 (EOL Dec 2019), connman 1.35, wpa_supplicant 2.6 and Chromium 68 (V8 6.8). Several well-known in-the-wild/high-profile bugs map directly onto these versions by upstream version number: FreeType CVE-2020-15999, libwebp CVE-2023-4863, zlib CVE-2018-25032, expat CVE-2022-25315 family, plus ~8 years of Chromium/V8 renderer bugs. LG may have backported fixes (version suffixes like `webos19`, `jcl4tv`), so treat these as *unverified exposure*, not confirmed exploitability. The browser/WAM path is the highest-risk surface: Chromium 68 renders third-party web content in apps (and the browser app), is started `--no-sandbox` (no renderer process sandbox), and exposes a DevTools port 9998 (reachability to be verified). Network-facing daemons (connman DNS proxy/DHCP, avahi mDNS, wpa_supplicant, Bluetooth stack) are the next tier. The trust store is 2018-vintage: expired and since-distrusted roots (Symantec, Certinomis, TrustCor, E-Tugra) remain trusted, and newer roots (GTS, ISRG X2) are missing unless the runtime certificate-update-manager supplies them. TLS stacks lack TLS 1.3 (OpenSSL 1.0.2 / 1.1.0) so modern servers requiring TLS 1.3-only or new chains may fail.

**Performance / functionality.** Chromium 68 means ES2018-era JS/CSS: no optional chaining, nullish coalescing, newer CSS (grid subgrid, container queries), modern WebAssembly features, etc., so current web apps/streaming UIs must be transpiled or fail; V8 6.8 is several JIT generations behind (Ignition/TurboFan only, no Sparkplug/Maglev), giving noticeably slower JS execution and heavier GC than current engines, and `--in-process-gpu` plus `--max-unused-resource-memory-usage-percentage=0` and resource-buffer caps indicate memory tuning for a constrained SoC. Kernel 4.4 and glibc 2.28 limit modern syscalls/features (e.g. no io_uring, older scheduler/cgroup). Old curl/OpenSSL/nghttp2 affect streaming-app network efficiency (no TLS 1.3 0-RTT, older HTTP/2). The stack is frozen per SoC (MediaTek/Realtek BSP), so updates beyond LG's webOS 5.x are not expected for this 2020 model.

*Caveats:* static version-to-CVE mapping only; no binaries executed; dropbear binary location unresolved; cert expiry computed against 2026-10-18; some CVE details marked (?) are from memory and unverified.
